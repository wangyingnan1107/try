# 小红书汇总分析报告缺陷诊断与修复方案

## 1. 逐行审计：原创内容丢失根因

### 1.1 Prompt 模板链路
- `server/llm_service.py:104-122`：聚合 Prompt 仅要求“整合输出”，未要求“必须保留原文证据片段”。
- 影响：模型可只给抽象总结，导致“openclaw安全方案控制”这类关键原文被泛化改写。

### 1.2 向量化/结构化策略链路
- 历史代码无 embedding/vector 流程。
- `server/llm_service.py:399-412`：只做字符串拼接，不做结构化分段、格式保留、权重标注。
- 影响：复杂格式（代码块、#话题#、@用户、外链、表情）在上下文中无显式标记，模型更容易忽略。

### 1.3 大模型调用参数链路
- `server/llm_service.py:419-427`（历史）：温度 `0.7`，且未显式 `max_tokens`。
- 影响：高温度提升发散与改写概率，且输出空间不稳定，关键细节更易丢失。

### 1.4 后处理过滤链路
- `server/llm_service.py:402-404`（历史）：评论仅保留 `len > 15`。
- 影响：短评论中的强信息（如“openclaw 安全方案控制在第3段”）被直接过滤。

### 1.5 存储与回显链路
- `server/database.py:45-53`：报告只存结构化 JSON，无原文证据字段。
- 影响：即使源帖存在核心段落，报告端没有“强制可追溯证据”保障。

## 2. 修复设计：结构化抽取模块

### 2.1 新增模块
- 新文件：`server/structured_extractor.py`
- 目标：在进入 LLM 前完成“结构化保留 + 权重标记 + 证据抽取”。

### 2.2 能力覆盖
- 图文混合：保留 `TITLE/BODY/OCR/COMMENTS/AUTHOR/URL` 多区块输入。
- 表情符号：统计 emoji 数并生成结构标注。
- `#话题#`：正则识别并单独标注 topic。
- `@用户`：正则识别 mention。
- 外链：识别 http/https 链接并标注。
- 代码块：识别 fenced code block 与 inline code 并高权重保留。

### 2.3 权重策略
- 标题 `1.35`、正文 `1.20`、OCR `1.10`、评论 `0.90`。
- 代码块 `1.45`，topic/mention/link 约 `1.0`。
- 输出统一上下文块：`[结构化标注] - 类型 | weight | 内容`。

### 2.4 原文证据保障
- 抽取 `source_evidence`（优先命中 openclaw/安全/方案/控制等词）。
- 聚合结果强制注入 `extended_insight` 的“原文证据片段”段落。

## 3. 量化指标与自动化验证

### 3.1 指标定义
- 召回率（关键片段召回）≥ 95%
- 贴主原创文本字符级保留率 ≥ 98%
- 关键安全方案段落（如“安全方案控制”）不得丢失

### 3.2 自动化测试范围
- `tests/fixtures/xiaohongshu_20_posts.json`：20 条采集格式数据，包含 openclaw 样本。
- `tests/test_structured_extractor.py`
  - 校验复杂格式提取与标注完整性。
  - 校验字符保留率阈值。
- `tests/test_aggregation_pipeline.py`
  - Mock LLM 返回不含证据文本，验证后处理仍补入“原文证据片段”。
  - 校验 openclaw 样本中“安全方案控制”在最终报告出现。

## 4. 5个工作日增量排期

### Day 1
- 交付：链路审计报告、指标口径、测试数据集规范。
- 联调：确认前后端兼容新增字段（可选字段不影响旧页面）。
- 回归：采集/单篇分析/聚合接口可用性。

### Day 2
- 交付：结构化抽取模块（分段、格式识别、权重标注、证据抽取）。
- 联调：接入聚合入口并保持 `/api/aggregate` 不变。
- 回归：数据库写入与报告读取不报错。

### Day 3
- 交付：LLM 聚合参数修正（低温、max_tokens、输入结构化）。
- 联调：多篇混合内容与 OCR 场景。
- 回归：旧报告展示、删除/下载接口。

### Day 4
- 交付：自动化测试（20条数据 + openclaw 回归）。
- 联调：Mock LLM 与真实接口双跑。
- 回归：异常 JSON 清洗、空字段兜底。

### Day 5
- 交付：CI 回归记录与灰度方案。
- 灰度：10% 数据集先行，监控召回率/保留率后放量到 100%。
- 回滚：保留旧逻辑开关，异常时切回历史拼接链路。

## 5. 上线灰度策略
- 灰度维度：按报告任务批次分流。
- 核心监控：`avg_char_retention_ratio`、`evidence_snippet_count`、聚合成功率。
- 阈值：任一指标低于基线立即回滚并触发告警。
